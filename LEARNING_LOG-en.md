## M01

- Completed: 2026-08-17
- Verification evidence:
  - `uv run ruff check .` passes; `uv run pyright` reports 0 errors; `uv run pytest`
    passes 13 tests;
  - `contracts.py` verified at runtime: every field is required, the `WorkerResult`
    schema lists all four fields under `required`, and `TaskRequest` rejects input
    with missing fields;
  - `uv run python -m evidence_worker.structured_agent` printed a single
    `WorkerResult` JSON object twice in a row on the Xiaomi MiMo endpoint
    (`mimo-v2.5`, chat completions + json_schema), with empty `evidence` and
    `errors` lists and the correct `task_id`;
  - MiniMax-M3 (with the previous `OPENAI_COMPATIBLE_API=responses` in `.env`)
    failed the same code with `ModelBehaviorError: Invalid JSON when parsing model
    output`: the model returned free text / markdown-wrapped JSON. A direct probe
    also confirmed that its chat completions endpoint silently ignores
    `response_format=json_schema`. Per the M01 lesson tip this is the expected
    behavior when structured output is unsupported; the exercise did not fall back
    to free text.
- One misconception corrected: assumed `output_type=WorkerResult` would enforce
  JSON output on any OpenAI-compatible endpoint; in practice structured output
  depends on the provider implementation, and an endpoint may accept the parameter
  without enforcing it.
- One open question: MiniMax-M3 structured-output compatibility is deferred to the
  M05 compatibility spike.

### M01 context boundary lists

Visible to the model (enters model context):

- the instructions string returned by `build_instructions` (role description, no
  fabricated evidence, empty-list requirements);
- the `model_input` passed to `Runner.run`, built only from the `task_id`,
  `question`, and `requested_source_ids` fields of `TaskRequest`;
- the output JSON schema of `WorkerResult` (generated by the SDK from
  `output_type` and sent with the request).

Local only (invisible to the model):

- `WorkerContext.logger` (a `logging.Logger` object);
- `WorkerContext.allowed_source_root` (absolute path of the fixtures directory);
- the AsyncOpenAI client, API key, and environment variables built by
  `load_learning_model()`.

Rationale: the SDK only puts instructions, input, and tool results into model
context; context is only exposed to local Python code through
`RunContextWrapper`. No code in this module writes local objects into
instructions, model input, or tool results.
